ТЗ для Claude Opus 5.5: Three.js Dinosaur Hide & Seek (Sandbox)
1. Общее описание
Браузерная 3D-игра на Three.js в жанре стелс-хоррор-песочница. Игрок — человек в процедурно сгенерированном городе, его цель — прятаться от динозавра (на первой итерации — один T-Rex). Конечной цели нет, это атмосферная бродилка-выживалка.

Технологический стек (предложение):

Three.js (r160+), ES-модули, Vite для сборки

Физика: Rapier3D (WASM, быстрый, хорошо дружит с Three.js) — альтернатива cannon-es

Контроллер игрока: собственный, кинематический character controller поверх Rapier

Аудио: Web Audio API (или Howler.js) — позиционный звук, вибрация рычания

UI: чистый HTML/CSS поверх canvas

Язык: TypeScript (строго)

3. Механики — детально
3.1 Процедурная генерация города
Сетка кварталов с варьирующейся шириной улиц и переулков (узкие переулки 2–3 м).

Здания: модульные префабы (коробки с вырезами под окна/двери), этажность 1–5, генерация внутренних этажей и лестниц.

Интерьеры: минимум — пустые комнаты с лестницами между этажами; двери как триггеры (открытие/закрытие).

Паркур-элементы: ящики, контейнеры, пожарные лестницы, кондиционеры, карнизы — всё проходимо/запрыгиваемо.

Канализация: подземный уровень, соединённый люками с поверхностью, узкие туннели. Переход между уровнями через люки/лестницы.

Сидирование: фиксированный seed для воспроизводимости (передаётся в URL-параметре).

Производительность: чанковая генерация (например, 32×32 м), LOD для дальних зданий, frustum culling, instanced meshes для повторяющихся объектов.

3.2 Контроллер игрока (от первого лица)
WASD + мышь (Pointer Lock).

Ходьба/бег (Shift), приседание (Ctrl) — присед снижает шум и высоту капсулы.

Прыжок, паркур:

coyote time (~100 мс),

jump buffer (~100 мс),

vault/mantle на уступы до 1.2 м,

ledge grab (опционально, если время позволит).

Коллизии: капсула, кинематический контроллер Rapier.

Шум игрока — ключевая механика: см. 3.4.

3.3 Динозавр (T-Rex)
Модель: любая бесплатная GLTF (Sketchfab CC0) или временный примитив (боксы/капсулы) с анимацией-заглушкой.

Навигация: NavMesh (можно построить через recast-navigation-js по геометрии города) ИЛИ упрощённый A* по сетке + локальный steering.

FSM / Behavior Tree состояния:

Patrol — случайные точки по городу;

Investigate — идёт к источнику шума;

Stalk — медленно крадётся к игроку, если «подозревает»;

Chase — быстрая погоня при прямом обнаружении;

Attack — при контакте (на первой итерации — «game over» экран и рестарт);

Search — после потери цели обыскивает область.

Сенсоры:

Слух: радиус слышимости зависит от громкости события игрока (шаги/бег/прыжок/дверь). События с координатой и «громкостью» отправляются в HearingSystem.

Зрение: конус обзора (~90°), дальность ~40 м, проверка line-of-sight через raycast; присед и укрытия снижают шанс обнаружения.

Память: последняя известная позиция игрока, время забывания.

Симуляция вибрации рычания — см. 3.5.

3.4 Система шума (Player Noise Emission)
Игрок генерирует события шума с параметрами {position, loudness, timestamp}.

Значения (примерные):

присед/шаг — 0.1

ходьба — 0.3

бег — 0.8

прыжок/приземление — 0.6

открытие двери/люка — 0.5

Динозавр «слышит» событие, если distance < loudness * maxRange (например, maxRange = 50 м).

На UI — индикатор «шумности» игрока (опционально, можно отключать для хардкора).

3.5 Симуляция вибрации от рычания (ключевая фича атмосферы)
У динозавра есть «аура» — при рычании (например, раз в 8–15 с в состоянии Investigate/Stalk) проигрывается позиционный звук.

Вибрация реализуется через:

Экранный shake (камера): амплитуда ∝ 1 / distance² с clamp.

Низкочастотный rumble через Web Audio (lowpass + gain по дистанции) — «чувство» приближения.

Gamepad haptics (если подключён) через GamepadHapticActuator.

Мобильная вибрация через navigator.vibrate (если мобильная версия — опционально).

Визуальный фидбек: лёгкое искажение постпроцессинга (опционально, chromatic aberration / vignette pulse).

Цель: игрок по вибрации должен примерно понимать, что динозавр рядом, но не видеть его.

3.6 Аудио
Позиционный звук (PannerNode): рычание, шаги динозавра (тяжёлые, с низкими частотами), шаги игрока, окружение (ветер, капли в канализации).

Фоновая атмосфера: хоррор-эмбиент, тишина в укрытиях.

3D-звук привязан к координатам источников.

3.7 Освещение и атмосфера
Время суток: туманный день, ночь (фонари, тени) или сумерки — для хоррора. 

Туман (FogExp2) для ограничения видимости и производительности.

Фонари на улицах, свет из окон, flicker-эффекты.

В канализации — темнота + фонарик игрока (клавиша F).

3.8 UI / HUD
Минимальный HUD: индикатор шума, возможно — «сердцебиение» при близости динозавра.

Экран смерти + рестарт.

Меню старта (seed, опции качества графики, чувствительность мыши).

Настройки: громкость, вкл/выкл вибрацию, качество теней.

4. Технические требования
Производительность: 60 FPS на средней машине (GTX 1060 / аналог), 30 FPS на слабой.

Целевой размер бандла — разумный (динозавр и префабы — оптимизированные GLTF, DRACO/KTX2).

Код: TypeScript strict, модульная архитектура, без глобальных синглтонов там, где можно обойтись DI.

Системы: ECS-лайт или обычные классы — на усмотрение Claude, но с чистыми интерфейсами между слоями (world / entities / ai / audio / ui).

Отладка: горячие клавиши — показать NavMesh, показать радиус слуха/зрения динозавра, teleport, spawn noise.

Сохранение: seed города в localStorage для возврата на ту же карту.

5. Объём первой итерации (MVP)
Процедурный город: сетка кварталов, здания с 1–3 этажами, лестницы внутри, узкие переулки, без канализации (заглушка-люк).

Контроллер игрока: ходьба/бег/прыжок/присед + базовый vault.

Один T-Rex: Patrol → Investigate → Chase → Attack, слух + зрение с LOS.

Система шума игрока.

Вибрация от рычания (камера shake + low-freq звук + дистанционная зависимость).

Позиционное аудио, базовая атмосфера (туман, ночь, фонари).

HUD, экран смерти, меню старта с seed.

Отладочные хоткеи.

6. Что можно отложить на вторую итерацию
Канализация как полноценный уровень.

Несколько видов динозавров + разные паттерны поведения.

Сохранение прогресса/достижения.

Полноценная анимация динозавра (сейчас — заглушка).

Постпроцессинг (виньетки, хроматическая аберрация).

7. Критерии приёмки
Игра запускается в браузере по npm run dev.

Город генерируется по seed, заходишь в здания, поднимаешься по лестницам, прыгаешь по паркуру.

T-Rex патрулирует, реагирует на шум игрока, теряет и ищет его.

При приближении T-Rex ощущается вибрация (камера + звук).

Контакт с динозавром → экран смерти → рестарт.

Стабильные 60 FPS на средней конфигурации.


Перед началом разработки скажи, насколько сложно будет реализовать следующие стили графики для игры

Retro PSX / PS1-style
Низкое разрешение рендера (320×240 с апскейлом), аффинные текстуры (дрожание), dithering, vertex jitter, туман для сокрытия дальней геометрии. Геометрия может быть простой, а стиль задаётся шейдерами. Сейчас очень модно в инди-хоррорах (см. Puppet Combo). Отлично маскирует слабые ассеты.

Silhouette / Shadow-play (силуэты)
Объекты — чёрные силуэты на светлом/туманном фоне (как Limbo, Inside). Реализм геометрии не нужен вообще — важна только форма.

Monochrome / Duotone (ч/б + один акцент)
Вся сцена в оттенках серого, только важные объекты (динозавр, фонари, кровь) — цветные. Реализуется одним шейдером постпроцессинга поверх обычной геометрии. Дёшево, атмосферно, очень «хоррорно». Геометрия может быть любой сложности — стиль задаётся цветом.
